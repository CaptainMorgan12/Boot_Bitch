# Boot Bitch legacy Qt3 GUI (`legacy/gui`)

Thin Qt3 frontend for the ported `boot-repair-legacy-helper`, built natively on
Debian 4.0 "Etch" with `qmake-qt3` + g++ 4.1 (C++98). Qt3 core widgets only:
no kdelibs, no Qt4/5/6 APIs, no QtSvg (PNG icons only).

> Qt3 note: the `Q3MainWindow`/`Q3ListView`/`Q3TextEdit`/`Q3TabWidget` class
> names belong to Qt4's Qt3-support module. Qt3 itself provides
> `QMainWindow`/`QListView`/`QTextEdit`/`QTabWidget`, which is what this
> frontend uses. Qt 3.3.7 also has no `QLabel::setWordWrap` (labels wrap via
> the `Qt::WordBreak` alignment) and no `QWidget::setVisible(bool)` (widgets
> are shown/hidden with `show()`/`hide()`).

## Layout

| Source | Purpose |
| --- | --- |
| `boot-bitch-legacy.pro` | qmake-qt3 project (shadow build, `MOC_DIR`/`OBJECTS_DIR`/`DESTDIR` = build dir) |
| `src/EvidenceParser.{h,cpp}` | Qt-free transcript parser + fail-closed `CapabilityModel` + unlock-result/error helpers |
| `src/DeviceInventory.{h,cpp}` | Qt-free read-only device inventory (`/proc/partitions`, `/proc/mounts`, `/proc/swaps`, `/sys/block`, `/dev/mapper`, `/dev/disk/by-uuid|by-label`; UUID, label and connection probes) |
| `src/HelperRunner.{h,cpp}` | Qt3 `QProcess` wrapper (merged stdout/stderr, line streaming, elevation prefix, modal `sudo -S -v` authentication, stdin secret for LUKS unlock) |
| `src/LegacyMainWindow.{h,cpp}` | `QMainWindow` + `QTabWidget` UI (systems/details/unlock, diagnostics, repair, chroot shell, file copy, logs/session/search, settings; Help -> About Boot Bitch dialog) |
| `src/main.cpp` | CLI, helper discovery, `--smoke-test` |
| `data/boot-repair-legacy-gui.desktop`, `data/boot-repair-legacy-*.png` | desktop entry and PNG icons (16/22/32/48, generated by `data/make-icons.py` as LANCZOS resizes of the modern master `data/icons/hicolor/1024x1024/apps/org.bootrepair.BootRepair.png`; the script fails fast when the master is missing) |

## Behavior

- **Global header** mirrors the modern window: the packaged hicolor icon is
  the real Boot Bitch artwork resized from the modern master PNG, and the
  window/app icon uses the same artwork (with a graceful no-icon fallback
  when the PNG is missing), **Boot Bitch** in the
  1.65x bold title font, the **Linux recovery and boot-repair utility** subtle
  line and the right-aligned framed **GUARDED REPAIR • 0.2.25** badge. It is
  sized so all seven tabs still fit at 1024x768 (the smoke layout gate).
- **Systems** mirrors the modern page: a **Systems** page heading with
  **Refresh Devices**, an **Available repair targets** section title above the
  read-only kernel inventory (Device, Size, Type, Filesystem, Mount, Note; the
  Filesystem column is never empty: component rows fall back through the
  mounted/swapped type, the read-only udev-probed type (an unmounted ext3 or
  a locked `crypto_LUKS` container is visible without opening the device),
  `[swap]` and `unknown`, and whole-disk rows aggregate their children
  (the primary Linux filesystem plus `+ LUKS` when an encrypted child
  exists, e.g. `ext3 + LUKS`)), the **Select Target / Unlock / Host Maintenance / Authorize**
  action row with the right-aligned **Committed target:** summary, the
  **Unlock status** frame directly below it and the **Selected drive details**
  pane (Drive, Detected target, Model/label, Status, Size, Connection,
  Filesystem, UUID, Mounts, Protection — all ten rows for every selection,
  unknown values rendering as `-`: Model/label falls back to the owning
  disk's model/label for partition/mapper rows, UUID falls back to the
  helper-confirmed root component's by-uuid identity, and Mounts joins the
  distinct mount targets, primary first) on the right. Drive selection comes
  from the list row (inspection), exactly like modern: selecting a disk
  inspects it and auto-resolves its best Linux root component (a dm/mapper
  device on that disk with a Linux filesystem first, then a Linux partition,
  then the disk itself), while selecting a partition/mapper inspects that
  component and keeps its owning disk as the target candidate. The resolved
  root is shown as **Detected target** and in the Select Target tooltip;
  Select Target is disabled with the exact reason when the drive is optical,
  the protected running host, or a locked LUKS container with no visible Linux
  filesystem (the modern "Unlock required before selection" rule). The
  protected running host is shown as `PROTECTED` and its Select Target/Unlock
  tooltips name **Host Maintenance** as the path; diagnostics never dead-end
  on an unclear error (the scope dialog names Select Target / Host
  Maintenance). **Unlock** auto-resolves the first locked LUKS component
  visible on the selected non-host drive from the world-readable udev metadata
  and opens it through the helper's `unlock <disk> <luks-device>` flow after a
  confirmation; the passphrase is entered hidden, travels only over the
  helper's standard input (never argv/logs), a rejected passphrase offers a
  retry and a successful unlock invalidates the cached diagnostics because the
  topology changed. There is no separate scope selector: the scope follows the
  committed repair target or Host Maintenance, so any selectable non-host disk
  can be committed while the protected running host stays excluded. The
  helper-confirmed facts from the last read-only diagnostics (physical drive,
  detected component, filesystem, system) fill the details pane and gate the
  auto-resolution (they win over the inventory guess).
- **Diagnostics** mirrors the modern Qt6 page: a **Diagnostics** heading row
  with the scope label (**Target: <disk> + <root component>**,
  **Host maintenance: <disk>** or **Target: none selected**) and **Run All**;
  the target configuration row (committed target only, probe-based Etch keys);
  then a horizontal splitter with the **Diagnostic checks** list (a single
  **Check** column showing the modern friendly diagnostic titles; the stable
  helper key stays internal for the command and the log, and the description
  appears in the selected-diagnostic pane and as the list tooltip) on the left
  and the **Selected diagnostic** pane on the right: dynamic title in the
  `sectionTitle` font, description, availability state (**Ready**, **Scope
  required** or **Running...**), a **Results** heading with the right-aligned
  **Run Diagnostic** button, the read-only results pane and the right-aligned
  **Copy Results** / **Save Results...** buttons. Save Results writes the
  current pane to a user-chosen file. There is no **Cancel running command**
  button (modern has none); the runner's cancel capability is kept for window
  close only. Run All / Run Diagnostic / Edit Target File are disabled while a
  helper command runs. There is no capability list and no availability filter,
  exactly like the modern page: the cached `Repair tool` lines remain the
  Repair tab's gating evidence. The target configuration row shows **Target
  configuration:** + a combo with the **Etch-era files** (`/etc/fstab`,
  `/etc/inittab`, `/boot/grub/menu.lst`, `/etc/crypttab`, `/etc/modules`,
  `/etc/network/interfaces`, `/etc/apt/sources.list`, `/etc/apt/apt.conf`) +
  **Edit Target File...**, and it is visible **only for a committed repair
  target** — Host Maintenance never shows or enables it (host repair has no
  target-file editing). Availability is probe-based: the helper's read-only
  diagnostics emit `Legacy config <key>: available|unavailable|<reason>` lines
  for the mounted target, so absent files are omitted from the combo with the
  helper's exact reason shown below it; before the first diagnostics run the
  row lists every Etch key and asks for a diagnostics run.   **Edit Target
  File...** opens the modal editor with the helper's guarded `config-read`
  content; **Save Target File** confirms, writes through the guarded
  `config-write` verb (mode/owner preserved, no symlinks, no creation) and
  invalidates the cached diagnostics. The edited content travels through a
  private mode-600 content file in the `.keys` directory
  (`--content-file <path> --content-owner <uid>`, up to 1 MiB) — never an
  argv element — and the GUI unlinks it on every completion path; the old
  argv form stays as a deprecated helper-side fallback.
- **Menus** mirror the modern structure: **File** carries **Refresh Devices**
  (F5), **Lock Administrator Session** and **Quit**; **View** carries the
  **Systems**, **Diagnostics**, **Logs** and **Settings** tab shortcuts, then
  **Auto-size Device Columns** and the checkable **Wrap Log Lines**; **Help**
  carries **Using Boot Bitch** (a width-constrained usage dialog adapted to the
  legacy frontend) and **About Boot Bitch** (a rich-text Qt3 dialog with the
  modern heading, the legacy-adapted guarded-repair description and the
  greyed modern-only features; there is no About tab). **Lock
  Administrator Session** drops the cached elevation decision and runs a
  best-effort non-blocking `sudo -k` (stdin closed, output discarded), logs the
  action and refreshes the inventory, so the next privileged action asks for
  the password again; it never prompts or blocks. **Auto-size Device Columns**
  sizes every column to its widest header/cell text (the last column still
  stretches to the viewport edge), and **Wrap Log Lines** is a second view of
  the Settings wrap toggle: changing either updates the other and the log view.
- **Authentication**: a plain interactive `sudo` is authorized once per scope
  through the modal hidden-input **Administrator authorization** dialog when
  Host Maintenance is entered or a repair target is committed; the password is
  fed to `sudo -S -v` over a pipe (never argv, never the transcript) and the
  cached session is reused by every later command, so **Run All never
  prompts**. The Systems action row and the Repair elevation frame carry the
  modern deferred-authorization affordance: an **Authorize** button plus a
  status label that re-establish the session without re-committing the target.
  Before every privileged command the runner probes the cached session
  non-blockingly (`sudo -S -v` with stdin closed, so an expired timestamp
  fails fast instead of blocking on a password read); an expired or refused
  session fails closed with the exact Authorize remedy, and only a transcript
  that actually shows a sudo session problem drops the cached decision. A
  cancelled or failed authorization never starts the command.
- **Repair** mirrors the modern page structure. A **Repair** heading with the
  shared scope label opens the page, followed by the modern plan paragraph
  verbatim ("Choose Full Repair stages in Settings..."), the **Full Repair
  plan** section (count label **No stages selected** / **N stages selected**,
  the numbered selected-stage list, the readiness text and **Configure Plan...**
  / **Run Full Repair**), then a horizontal splitter with the **Individual
  repair tools** list (columns **Tool** | **Full Repair**) on the left and the
  **Selected tool** pane (dynamic title, per-tool button, description and plan
  status) on the right; the pane has a 300px floor and the dynamic title wraps
  with the Qt3 `Qt::WordBreak` alignment (there is no `QLabel::setWordWrap` in
  Qt 3.3.7), so every tool title fits at 1024x768 without clipping. The legacy-only **Privilege elevation** frame with
  **Re-check elevation** and the deferred **Authorize** control, the scope/gate
  hint and the confirmation note close the page. The tools list shows all 13
  modern tools in the modern order; the 9 legacy-runnable stages
  (**Validate**, **Check File Systems**, **Repair Dependencies**, **Complete
  Configuration**, **Refresh Metadata**, **Simulate and Upgrade**, **Rebuild
  Initramfs**, **Regenerate GRUB**, **Restore Graphical Login**) run through
  the helper, while DKMS / EFI / extlinux / boot-stack are display-only rows
  whose run button stays disabled with the exact reason (the cached
  capability reason or the frontend omission). The display tool is the
  legacy host-scope SysV stage: it runs only with Host Maintenance active,
  the `display` capability line available and the `host-maintenance` feature
  available (the guarded plain-chroot fallback satisfies it on BIOS-only
  hosts); the offline target form stays disabled with the host-scope
  reason and its plan status reads **Host-scope stage - not part of the
  Full Repair plan**. The **File system repair** tool is the legacy
  read-only `fs-inspect` check and its plan status reads
  **Read-only check - not part of the Full Repair plan**. The Full Repair
  column mirrors the Settings **Full Repair plan** checkboxes
  (**Enabled in Settings** / **Disabled in Settings - enable it to include this
  stage**), the validate tool reads **Always preflight**, boot-stack reads
  **Manual recovery tool**, and any unavailable capability overrides the status
  with **Unavailable: <reason>**. A tool runs only when the scope is ready
  (committed target or Host Maintenance), no command is running, the
  administrator session is active and the cached capability line for its key
  says `available` for the *current* selection (host `initramfs`/`grub`/`display`
  additionally require the helper's `Legacy feature host-maintenance:` probe);
  otherwise the tooltip and the pane name the exact reason. Write actions ask
  for confirmation, the helper keeps its runtime preflights, and a repair that
  is not proven `unchanged` invalidates the cache.
- **Full Repair plan** runs the six legacy stages in helper rank order
  (`dpkg-configure`, `fix-broken`, `apt-update`, `apt-upgrade`, `initramfs`,
  `grub`) in one `repair <disk> <root> <stages...>` / `host-repair ...`
  invocation. The Settings checkboxes use the modern labels and persist through
  Qt3 `QSettings` under the modern-compatible keys (`repair/dpkgConfigure`,
  `repair/fixBroken`, `repair/refreshMetadata`, `repair/upgradePackages`,
  `repair/initramfs`, `repair/grub`); **Configure Plan...** switches to
  Settings. **Run Full Repair** is enabled only when at least one checked stage
  is available, the scope is ready, no command is running, the administrator
  session is active and the cached read-only diagnostics are fresh; otherwise
  the readiness label and the tooltip name the exact reason (the default text
  is the modern "Run All diagnostics..." string and the ready text is the
  modern "Ready: required cached read-only diagnostics..." string). After the
  plan completes (success or aborted, once after the last stage like modern
  finishFullRepairPlan) the scope's cached diagnostics are invalidated and
  one quiet Run All is scheduled when the auto-refresh setting, the session
  and the idle state allow it (never prompting). The
  confirmation dialog lists the stages in execution order first; a stage that
  fails stops the plan, and the helper keeps every runtime preflight.
- **Repair result popup**: starting an individual tool or Run Full Repair opens
  a modal Qt3 dialog titled with the tool name (or **Full Repair**) with a
  bold status line, the streamed helper transcript in a read-only monospace
  pane and a **Close** button that is enabled when the command finishes
  (success: "Privileged operation completed successfully. Administrator
  authorization remains active for this session."; failure: "Privileged
  operation stopped with an error..."). Closing the popup early leaves the
  command running; the Logs tab always receives the complete transcript. The
  popup is never opened by `--smoke-test`, and diagnostics keep their in-tab
  **Results** behavior.
- **Chroot Shell / Host Shell** runs one reviewed command string through the
  helper's guarded `shell <disk> <root> <command>` (offline target) or
  `host-shell <disk> <root> <command>` (running host, with an explicit
  confirmation). The page heading, tab label, notice, button text
  (**Run Command** / **Run on Host**) and command heading switch with the
  scope, exactly like the modern `updateChrootShellMode`; the command is passed
  as a single argument (no shell interpolation by the GUI) and the controls are
  enabled only when the scope is committed, the cached administrator session
  is active and the scope's `Legacy feature shell:` / `host-shell:` probe
  reports `available`; otherwise every control stays greyed with the exact
  reason and the helper's runtime preflights are never weakened. On Etch the
  probes are unavailable (`unshare`/`timeout --foreground` are missing), so
  the tab stays greyed with the probe reason. **File Copy** mirrors the modern
  tab with every control greyed and the exact `Legacy feature file-copy:`
  probe reason.
- **Logs** streams the merged helper output with the modern 1:1 kind filter
  (**All entries** / **Diagnostics** / **Repairs** / **File system repair** /
  **Package repair** / **File copy** / the 16 diagnostic section titles), a
  **Search log:** substring filter (case-insensitive) and a **Session logs**
  list: the live session is the first entry, earlier files in the log
  directory are listed read-only and selectable. Every register entry is
  tagged at capture time: lines while a diagnostic command runs are
  Diagnostics entries whose section key follows the stream's
  `Diagnostic: <key>` markers, lines while a repair action runs are Repair
  entries carrying the helper stage (the Full Repair run carries the whole
  stage set), and everything else stays application text. The workflow
  filters map fs-inspect to **File system repair** and
  fix-broken/dpkg-configure/apt-update/apt-upgrade to **Package repair**;
  **File copy** has no lines in this frontend (the entry stays for the 1:1
  order). The **Application log** row puts the section title left and
  **Save As...** / **Clear Register** right above the search/filter row
  (Save As always writes every entry of the live register; Clear Register
  clears the live register/view only and prior files are never modified).
  **New Session Log**
  closes the active file (it becomes a prior session; the next log entry
  creates a new timestamped file), **Add Note** appends a free-text
  `NOTE: <text>` entry, **Delete** removes only the selected prior file after a
  confirmation (the live file and anything outside the log directory are
  refused), and **Refresh** re-lists the directory. A framed **Viewing a prior
  session log (read-only)** banner is shown only while a prior file is
  displayed.
- **Settings** shows the functional **Device discovery** filters (modern
  wording, default on: non-Linux drives, removable/USB storage and
  encrypted-before-unlock), the functional **Diagnostics** auto-refresh toggle
  (default on), the **Wrap long log lines** toggle, the mandatory safety
  controls, and the read-only **Host capabilities and dependencies** group
  (Distribution, Package manager family and **Privileged authorization
  support: sudo / gksu (no KAuth on this frontend)** summary labels, the
  6-column **Feature | Command | Scope | Status | Suggested package |
  Notes** table mirroring the modern 23 probe rows plus the legacy
  `Process namespace isolation / unshare` row, a **Refresh Capabilities**
  button that re-runs the read-only PATH probes (nothing is executed) and
  the modern-tooltip **Install Missing Support...** button, present but
  disabled because host installs are forbidden) and the legacy-only
  read-only **Application configuration**
  group. The three filters, the wrap toggle (Settings checkbox and the View
  menu item) and the auto-refresh toggle persist through Qt3 `QSettings`
  under the modern-compatible key names (`devices/showNonLinux`,
  `devices/showRemovable`, `devices/showEncrypted`, `logs/wrapLines`,
  `diagnostics/autoRefreshStale`), and every toggle handler saves
  immediately (plus a final flush on window close). Qt 3.3.7 stores each
  settings group in its own per-user file under `~/.qt/` named after the
  group — `devicesrc`, `logsrc`, `diagnosticsrc`, `repairrc` (the
  `setPath("boot-bitch", "boot-repair", User)` organization/application pair
  names the scope, not one boot-bitchrc file) — so overrides survive restart
  and `dpkg -r`/`dpkg -i` reinstalls never touch them. The unlock passphrase
  reaches the helper through a mode-600 keyfile argument
  (`unlock --key-file <path> --key-owner <uid>`; the helper verifies a
  regular caller-owned file — owner equals the passed uid, SUDO_UID or the
  effective uid — reads it with the newline-tolerant key handling and deletes
  it before the open attempt) because Qt 3.3.7's QProcess cannot deliver
  stdin; `--smoke-test` runs with settings isolation so the user's persisted
  files are neither read nor written during the smoke. Cycle 10: every new UI
  string is ASCII-only (`|` separators, `[OK]`/`[FAIL]`/`[-]`,
  `==== REPAIR ====` brackets) for Etch's fonts; the Logs Save As... starts
  in a writable /host mount when one exists (fallback: the log directory);
  long confirmations use a shared wrapped dialog. The filters hide the
  owning drive's rows (a hidden drive hides its partitions/mappers) with the
  modern rule — an encrypted drive stays visible while "show encrypted" is on
  even without a Linux candidate — and the selected/committed target state
  stays valid when its row is hidden. Automatic diagnostics regeneration
  schedules one quiet Run All when the setting is on, a scope is ready, no
  command is running and the administrator session is already active, after:
  entering Host Maintenance, committing a repair target (both change the
  scope identity), a LUKS unlock, a target configuration edit, and any
  repair whose change status invalidates the cached diagnostics; it never
  opens an authorization prompt by itself and logs the exact skip/pending
  reason otherwise. The page is scrollable (Qt3 `QScrollView`, the Qt3
  stand-in for the modern `QScrollArea`).
- The Help menu's **About Boot Bitch** dialog carries the modern heading
  **Boot Bitch <version>** and **Developer: CaptainMorgan12** with the
  legacy-adapted guarded-repair description; there is no TUI fallback in the
  package (the shell-only launcher is no longer shipped).

### Frame titles on the Etch Qt3 style (clipping workaround)

Qt3's KDE/Etch style draws a `QGroupBox` title on the upper frame line with its
top half above the frame, which clipped the group titles at 1024x768 (the
Systems **Available repair targets** section-title label was the only clean
title). Every legacy group frame is therefore titleless and carries a
`sectionTitle`-style label (1.2x bold) as its first row, using the same
pattern as the Systems page; the Repair page is also wrapped in a Qt3
`QScrollView` like Settings because the plan + tools + elevation sections
exceed the contract height. Every section title expands horizontally and
keeps `Qt::AlignLeft`, so its text starts at the same left edge as the
frame content below it (the Repair-page centered-title regression is
locked in by a left-edge geometry probe). `verifyLayout` iterates every tab
(`setCurrentPage`) and checks each page's section-title labels for width and
page/content containment — so a clip on a non-active tab fails the smoke too —
while wrapping titles (`Qt::WordBreak`) are exempt from the single-line width
check (they break onto a second line instead of clipping and still pass the
containment check), and a non-empty future `QGroupBox`
title must keep half a line of top clearance or the smoke fails. The smoke
also re-verifies all 13 tool titles plus the `Select a repair tool`
placeholder against the Selected tool pane.

placeholder GUI binary so the package layout contract stays testable.
