# Boot Bitch legacy Qt3 GUI (`legacy/gui`)

Thin Qt3 frontend for the ported `boot-repair-legacy-helper`, built natively on
Debian 4.0 "Etch" with `qmake-qt3` + g++ 4.1 (C++98). Qt3 core widgets only:
no kdelibs, no Qt4/5/6 APIs, no QtSvg (PNG icons only).

> Qt3 note: the `Q3MainWindow`/`Q3ListView`/`Q3TextEdit`/`Q3TabWidget` class
> names belong to Qt4's Qt3-support module. Qt3 itself provides
> `QMainWindow`/`QListView`/`QTextEdit`/`QTabWidget`, which is what this
> frontend uses.

## Layout

| Source | Purpose |
| --- | --- |
| `boot-bitch-legacy.pro` | qmake-qt3 project (shadow build, `MOC_DIR`/`OBJECTS_DIR`/`DESTDIR` = build dir) |
| `src/EvidenceParser.{h,cpp}` | Qt-free transcript parser + fail-closed `CapabilityModel` + unlock-result helpers |
| `src/DeviceInventory.{h,cpp}` | Qt-free read-only device inventory (`/proc/partitions`, `/proc/mounts`, `/proc/swaps`, `/sys/block`, `/dev/mapper` symlinks) |
| `src/HelperRunner.{h,cpp}` | Qt3 `QProcess` wrapper (merged stdout/stderr, line streaming, elevation prefix, stdin secret for LUKS unlock) |
| `src/LegacyMainWindow.{h,cpp}` | `QMainWindow` + `QTabWidget` UI (systems/targets/unlock, diagnostics, repair, logs, about) |
| `src/main.cpp` | CLI, helper discovery, `--smoke-test` |
| `data/boot-repair-legacy-gui.desktop`, `data/boot-repair-legacy-*.png` | desktop entry and PNG icons (generated by `data/make-icons.py`) |

## Behavior

- **Systems** shows the world-readable kernel inventory (never opens a block
  device), the helper-confirmed facts parsed from the last diagnostic run
  (`System:`, `Physical drive:`, `Detected component:`,
  `Running host root mount source:`, ...) and a **LUKS unlock** control:
  the helper's `unlock <disk> <luks-device>` runs after a confirmation, the
  passphrase is entered hidden and travels only over the helper's standard
  input (never argv/logs), a rejected passphrase offers a retry, and a
  successful unlock invalidates the cached diagnostics because the target
  topology changed. Unlock stays disabled for the protected running host.
- **Diagnostics** lists the 13 `Repair tool <key>: available|unavailable|<reason>`
  lines with an **all/available/unavailable filter**; unavailable rows are
  greyed and show the helper's probe reason verbatim. `Repair capability
  evidence` lines feed the reason/tooltip; **Run All diagnostics** is the
  read-only evidence source and **Cancel** stops a running command.
- **Repair** shows the resolved **elevation state** (`gksu --sudo-mode`,
  `gksudo`, `sudo`, `su`, root or unavailable) with a **Re-check elevation**
  button that re-probes and surfaces the exact error, and exposes only the
  legacy-supported commands (`validate`, `diagnose`, `fs-inspect`,
  `fix-broken`, `dpkg-configure`, `apt-update`, `apt-upgrade`, `initramfs`)
  in the running-host (`host-*`) or offline-target form. A button is enabled
  only when the cached capability line for its key says `available` for the
  *current* selection and no repair has invalidated the cache; otherwise the
  tooltip names the exact reason. Write actions ask for confirmation; the
  helper keeps its runtime preflights. The modern-only features (Full Repair
  plan, snapshots, file copy, chroot shell, host default/reboot, EFI/UKI/
  extlinux, Settings) are listed **greyed with their reasons**.
- **Logs** streams the merged helper output with an **all/errors filter**
  (Save log always writes every entry) and mirrors it to
  `~/.boot-repair-legacy/logs/<stamp>.log` (`--log-dir` overrides).
- **About / TUI** documents the no-X fallback: `boot-repair-legacy --tui`.

## Modern-GUI parity

The Qt6 Boot Bitch tabs map onto this frontend where Qt3 allows it:

| Modern GUI | Legacy Qt3 | Notes |
| --- | --- | --- |
| Systems (device tree, selected drive details, Unlock status, Select Target/Unlock/Authorize) | Systems (inventory, scope/target, unlock + status) | target is typed/selected instead of a tree; elevation replaces Polkit "Authorize" |
| Diagnostics (check list, Run All/Run Diagnostic, results) | Diagnostics (capability list + Run All, raw evidence) | capability lines are the legacy result source |
| Repair (Full Repair plan, individual tools, gating) | Repair (individual gated tools) | no combined plan on the legacy helper |
| Logs (entry-kind filter) | Logs (all/errors filter) | full log always saved |
| Settings | — | no persistent settings; CLI flags/env only |
| Snapshots / Chroot Shell / File Copy | — | greyed on the Repair tab with probe/helper reasons (Etch has no `unshare`/`timeout`/`rsync`/Btrfs evidence) |

Deliberate omissions (documented, not hidden): Full Repair plan, snapshots,
file copy, chroot shell, host default/reboot, EFI/UKI/extlinux repair and the
Settings tab. They never appear as enabled controls and the action table keeps
the exact legacy command set.

## Build

On the Etch guest (native, unprivileged):

```sh
mkdir -p Development/build-legacy-package/gui && cd Development/build-legacy-package/gui
BOOT_REPAIR_LEGACY_VERSION=0.2.25 qmake-qt3 /path/to/legacy/gui/boot-bitch-legacy.pro
make
```

or build the package (which does the above and stages the binary/desktop/icons):

```sh
scripts/package-legacy.sh --output /root/legacy-build
```

`scripts/package-legacy.sh --dry-run` on a host without Qt3 stages a
placeholder GUI binary so the package layout contract stays testable.

## CLI

```
boot-repair-legacy-gui [--helper PATH] [--elevate PREFIX|none] [--no-elevate]
                       [--host-disk PATH] [--host-root PATH] [--log-dir DIR]
                       [--smoke-test]
boot-repair-legacy-gui --help | --version | --print-config
```

`--help`, `--version` and `--print-config` work without an X display.
`--smoke-test` runs `host-diagnose all` followed by `host-validate` through the
helper, verifies the unlock/elevation/filter controls and the 1024x768 layout
(group titles, button text, list columns and combos are checked with font
metrics and widget geometry) and prints the combined result; it needs a display
(Xvfb with a 1024x768 screen is sufficient). Elevation order is `sudo -n`
(only when already authorized), `gksu --sudo-mode`, `gksudo`, `sudo`, `su`;
`--no-elevate` runs the helper directly. No secret is ever placed on a
command line; the LUKS passphrase uses stdin only.

## Tests

`legacy/tests/test-gui-contract.sh` (fast ctest
`boot-repair-legacy-gui-contract`) compiles the Qt-free parser/inventory
modules with plain `g++ -std=c++98 -Werror`, runs the fixture assertions in
`legacy/tests/gui-parser-test.cpp` (capability parsing, fail-closed gating,
change-status invalidation, device inventory, unlock-result markers) and checks
the Qt3-only source contract, the legacy command set, the parity controls
(unlock/elevation/filters/greyed features) and the layout guards. The full Qt3
compile and the extended smoke test run on the Etch guest.

Built natively on the Etch guest (g++ 4.1.2, qmake-qt3 1.07a/Qt 3.3.7) and
installed from the `.deb`; under Xvfb `--print-config` resolved the running
host (`/dev/hda` + `/dev/mapper/root`) and `--smoke-test` ran
`host-diagnose all` + `host-validate` through the helper
(`SMOKE OK: 13 capability lines parsed; host-validate: ok`), with the GUI
process at 12 460 KiB RSS. Etch's udev exposes `/dev/mapper/<name>` as block
device nodes (no symlinks), so the inventory resolves dm targets via
`/sys/block/dm-N/dev`; evidence lives in the private
`Development/release-0.2.25/etch-legacy/gui-*.log` capture.

GUI polish pass (same day): the extended smoke at 1024x768 reports
`SMOKE OK: host-diagnose: 13 capability lines parsed; host-validate: ok;

failed on the pre-compaction layout (panes/buttons below the page bottom) and
